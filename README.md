# 敏感数据识别性能提升实测：非结构化数据结果对比

## 行业现状
各厂商均具备自己的敏感数据识别引擎。从公开资料看，针对非结构化数据的敏感数据识别能力，各厂商的实现思路大体一致。这种方案在小数据量场景下差异不明显，但在大数据量全量扫描时会出现性能衰减，进而导致资源浪费、扫描任务超时等问题。

## 测试说明
- **数据梯度**：1M～500M 文本数据，覆盖从小批量测试到企业级大数据场景。
- **测试场景**：无匹配、微量匹配、适量匹配、全量匹配，覆盖日常工况与极限压力场景。
- **对比基准**：传统方案 vs 优化方案。

> 传统实现说明：以下传统实现方式用于模拟未做优化的初版实现，其性能数据仅作参考，用于与优化后的 Demo 进行对比，不代表现有厂商的实际性能。

> 验证说明：从互联网选取 15 个常见规则作为 Demo 验证；仅针对非结构化数据部分的识别性能；所有验证场景均在本机单进程执行，无集群、无硬件加持、无数据修饰，真实客观地呈现优化后的性能差距。

## 场景一：无匹配（无敏感数据）

## 技术核心总结

从上述 Demo 验证结果看，性能提升约 10 倍（全量匹配出现的概率极低）。在全场景下，传统实现所采用的规则仍存在较大优化空间。传统实现效率偏低，在实际落地中会直接造成三大行业痛点：巡检效率极低、服务器算力浪费、风险研判滞后。

以一家规模较大的企业为例，若要求每天完成 1 PB 数据处理，按此优化效果估算，每月可节省成本 3 万元以上。
